# Contributing

## Contribution Paths

- Documentation updates
- Bug fixes
- Feature proposals
- Performance and security improvements
- Tooling and developer experience enhancements

## Required Workflow

1. Create or select an issue.
2. If change is non-trivial, draft RFC or ADR.
3. Implement with tests and documentation updates.
4. Open PR using the provided template.
5. Complete quality gates and required reviews.

## Definition Of Done

- Tests pass and coverage thresholds are met
- Security checks pass
- Documentation updated
- Release notes prepared when user-facing impact exists

## Review Expectations

- Be specific, kind, and actionable
- Request data for major claims
- Prefer small, iterative changes

## Commit And Branch Rules

Follow engineering/standards.md for naming, commit format, and branch strategy.
